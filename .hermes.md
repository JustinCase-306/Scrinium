# Scrinium — Projektregeln

Regeln, die beim Bauen von Scrinium immer gelten. Allgemeines steht im
globalen Gedaechtnis, das hier nicht wiederholt wird.

## 1. Fenster nie sichtbar aufpoppen lassen

Der Nutzer arbeitet am Rechner. Jedes Fenster, das ich zum Testen
aufmache, unterbricht ihn.

- **Start minimiert:**
  ```python
  startupinfo = subprocess.STARTUPINFO()
  startupinfo.dwFlags |= subprocess.STARTF_USESHOWWINDOW
  startupinfo.wShowWindow = 6            # SW_MINIMIZE
  subprocess.Popen([exe], startupinfo=startupinfo,
                   creationflags=subprocess.CREATE_NO_WINDOW)
  ```
- **Beweis, dass ein Fenster erzeugt wurde:** Der WebView2-Kindprozess
  erscheint in `tasklist`. `MainWindowHandle` ist bei pywebview **immer 0**
  und taugt nicht als Nachweis.
- **DOM lesen:** ausschliesslich `window.evaluate_js(...)`. Damit geht
  alles, ohne dass das Fenster sichtbar wird.

## 2. Builds brauchen ein leeres PYTHONPATH

Steht global ein Agenten-Pfad in `PYTHONPATH`, zieht PyInstaller deren
`cffi` mit. Die fertige EXE startet dann mit:

```
Version mismatch: cffi 2.0.0 ... 2.1.1
```

- In `build.bat`: `set "PYTHONPATH="` und `set "PYTHONHOME="` gleich am
  Anfang.
- In der Shell: `env -u PYTHONPATH -u PYTHONHOME .venv/Scripts/python.exe ...`

`build.bat` macht das seit 2026-10-05 von selbst.

## 3. Code auf Englisch, ausser bei Anzeigetext

Auf Deutsch bleiben **nur**:

- Anzeigetexte, die der Nutzer liest („Download l\u00e4uft noch")
- Sprachschlüssel in `scrinium/sprache/de.py` (`fenster.titel`)
- Kommentare und Docstrings
- Verzeichnisnamen (`tools/_downloadsorter`)

**Umbenennen nie per Regex über den ganzen Baum.** Das hat mehrfach
schiefgehen: `texte.sag` wurde zu `textssag`, vier Tests verloren ihr
`test_`-Präfix, am Ende waren 57 Tests kaputt. Der Weg, der
funktioniert:

```python
class Renamer(ast.NodeTransformer):
    def visit_Attribute(self, node):
        self.generic_visit(node)
        if node.attr == "alter_name":
            node.attr = "new_name"
        return node

baum = Renamer().visit(ast.parse(quelle))
ast.fix_missing_locations(baum)
neu = ast.unparse(baum)
```

Der AST prüft, was wirklich ein Attributzugriff ist, und lässt
Zeichenketten und Kommentare in Ruhe.

| Test | Warum |
|---|---|
| `test_fenster_dom.py` | liest den echten DOM des Fensters (22 Prüfungen) |

Die DOM-Prüfungen brauchen ein Fenster. Sie starten es minimiert und
lesen per `evaluate_js`.
